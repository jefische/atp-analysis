# ATP Analysis
This repository explores decision tree models to predict ATP match results using data from Jeff Sackmann's publically provided database, including Elo ratings.

Data pulled from:
https://github.com/JeffSackmann/tennis_atp

Elo script pulled from:
https://github.com/sleepomeno/tennis_atp/blob/master/examples/elo.R

## Overview

Each record in the raw data is a single ATP match with its winner, loser, and match statistics. To turn this into a prediction problem, the winner of each match is randomly assigned to either `Player1` or `Player2`, and the model predicts `P1Wins`.

Features are built so that they only use information available *before* the tournament in question:

- **Elo ratings** — computed match by match across 2015–2019, with a K-factor that decays as a player accumulates matches and a 1.1x multiplier for Grand Slams.
- **Rolling year-over-year stats** — for each player entering each tournament, percentage of matches won, percentage of sets won, and average aces per set over the prior 365 days.
- **ATP rank** at the time of the match.

## Results

| Model | Test accuracy |
| --- | --- |
| Logistic regression | 76.4% |
| Gradient boosted trees (`gbm`, 1,073 trees) | 78.8% |
| Gradient boosted trees (tuned via `caret` grid search) | 79.3% |

Elo ratings carry the highest relative influence in both boosted models.

The full write-up with code, plots, and commentary is in [ATP_Analysis.md](ATP_Analysis.md).

## Data

The five season files hold 14,440 matches in total. After dropping Davis Cup and ATP Next Gen Finals matches (different formats and scoring), along with walkovers, in-progress, retired, and defaulted matches, the modeling dataset covers 10,207 matches across 267 tournaments, from Doha 2016 through the 2019 Tour Finals.

The train/test split is chronological rather than random, since the features look backward in time: the first 201 tournaments (7,677 matches) are used for training and the remaining 66 (2,530 matches) for testing.

## Running the analysis

Requires R with `tidyverse`, `lubridate`, `knitr`, `rmarkdown`, `gbm`, and `caret`.

```
Rscript -e "rmarkdown::render('ATP_Analysis.Rmd')"
```

A full knit takes a while — the feature loop runs over every player in every tournament, and the grid search fits 54 model configurations under 5-fold cross validation. To work on the modeling sections alone, enable the `skip_load` chunk, which reads the cached `git_data/r_for_modeling.csv` instead of rebuilding the features.

## Possible extensions

The dataset carries several match statistics this analysis does not use, most notably break points, break points saved, and first and second serve percentages. Beyond adding features, a natural next step would be to look at confidence in the predictions rather than accuracy alone.
